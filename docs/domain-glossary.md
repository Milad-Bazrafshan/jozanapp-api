# واژه‌نامه دامنه

نام‌های این سند باید در کد، API، دیتابیس و رابط کاربری با یک معنای ثابت استفاده شوند.

## سازمان و هویت

| اصطلاح | تعریف | نکته |
|---|---|---|
| Tenant | مرز امنیتی و مالکیت داده یک مشتری | تمام داده‌های تجاری به Tenant تعلق دارند |
| Educational Institution | مرکز آموزشی متعلق به Tenant | در MVP رابطه Tenant و مؤسسه یک‌به‌یک است |
| Branch | شعبه فیزیکی یا اجرایی مؤسسه | بعضی کلاس‌های آنلاین نیز به شعبه مسئول متصل‌اند |
| User Account | هویت ورود سراسری کاربر | داده آموزشی نگه نمی‌دارد |
| Person | پرونده یک شخص داخل یک Tenant | بین Tenantها به اشتراک گذاشته نمی‌شود |
| Tenant Membership | اتصال حساب ورود به Person و Tenant | وضعیت و دسترسی ورود به همان Tenant را تعیین می‌کند |
| Role | مجموعه‌ای از Permissionها | نقش می‌تواند سفارشی یا سیستمی باشد |
| Access Grant | تخصیص نقش در یک محدوده | MVP محدوده Tenant یا Branch را پشتیبانی می‌کند |

## ساختار آموزشی

| اصطلاح | تعریف | مثال |
|---|---|---|
| Academic Period | بازه رسمی اجرای آموزش | سال ۱۴۰۵–۱۴۰۶، ترم پاییز |
| Program | برنامه یا مسیر آموزشی | دوازدهم تجربی، انگلیسی بزرگسالان، تعمیر موبایل |
| Course | واحد محتوایی قابل ارائه | ریاضی دوازدهم، English B2، برق خودرو |
| Course Offering | ارائه یک Course در بازه و شعبه مشخص | ارائه English B2 در پاییز شعبه مرکزی |
| Class Section | گروه اجرایی یک Course Offering | گروه عصر استاد احمدی |
| Student Group | گروه سازمانی دانش‌آموزان مستقل از یک درس | کلاس دوازدهم A؛ خارج از هسته MVP مگر نیاز قطعی |

`Program` مفهوم عمومی محصول است. اطلاعات مدرسه‌ای مانند مقطع، پایه و رشته، طبقه‌بندی‌های اختیاری Program هستند و نباید استفاده محصول در آموزشگاه زبان یا فنی‌وحرفه‌ای را محدود کنند.

## زمان‌بندی و اجرا

| اصطلاح | تعریف |
|---|---|
| Class Schedule | مجموعه قوانین برنامه یک Class Section |
| Schedule Rule | یک قانون تکرار با زمان، استاد و محل مشخص |
| Class Session | جلسه واقعی برنامه‌ریزی‌شده یا برگزارشده در یک تاریخ مشخص |
| Schedule Exception | حذف یا استثناکردن یک رخداد از قانون تکرار |
| Session Override | تغییر استاد، زمان یا محل فقط برای یک جلسه |
| Session Instructor | استاد تخصیص‌یافته به یک جلسه مشخص |

قانون اصلی: `ClassSection` هویت کلاس، `ScheduleRule` انتظار تکرارشونده و `ClassSession` واقعیت اجرایی است.

## اشخاص و ثبت‌نام

| اصطلاح | تعریف |
|---|---|
| Student Profile | نقش آموزشی Person به‌عنوان دانش‌آموز |
| Instructor Profile | نقش آموزشی Person به‌عنوان استاد |
| Guardian Profile | نقش Person به‌عنوان ولی |
| Student Guardian | رابطه تاریخ‌دار ولی و دانش‌آموز همراه سطح دسترسی |
| Enrollment | عضویت تاریخ‌دار دانش‌آموز در Class Section |
| Enrollment Transfer | پایان کنترل‌شده عضویت قبلی و ایجاد عضویت جدید |

`Enrollment` جایگزین فیلد `classId` در دانش‌آموز است و تاریخچه عضویت را حفظ می‌کند.

## حضور

| اصطلاح | تعریف |
|---|---|
| Attendance Record | وضعیت حضور یک دانش‌آموز در یک Class Session |
| Presence Status | حاضر، غایب، غیبت موجه یا ثبت‌نشده |
| Delivery Mode | حضوری، آنلاین یا ترکیبی |
| Timing Detail | دقیقه تأخیر یا خروج زودهنگام |

آنلاین‌بودن روش شرکت است و تأخیر ویژگی زمانی؛ این دو نباید با وضعیت حاضر/غایب در یک enum ترکیب شوند.

## آزمون و نمره

| اصطلاح | تعریف |
|---|---|
| Question | هویت پایدار یک سؤال در بانک سؤال |
| Question Version | محتوای تغییرناپذیر یک نسخه از سؤال |
| Assessment | آزمون، کوییز یا تکلیف قابل ارزیابی |
| Assessment Target | قاعده انتخاب مخاطبان پیش از انتشار |
| Assessment Participant | دانش‌آموز قطعی آزمون پس از انتشار |
| Assessment Attempt | یک نوبت شرکت دانش‌آموز در آزمون |
| Student Response | پاسخ به یک سؤال نسخه‌شده |
| Assessment Result | نتیجه قطعی یا در حال تصحیح شرکت‌کننده |
| Result Publication | انتشار کنترل‌شده نتیجه برای مخاطب |

انتشار آزمون باید سؤال‌ها، تنظیمات مؤثر و شرکت‌کنندگان را ثابت کند. ویرایش‌های آینده نباید آزمون تاریخی را تغییر دهند.

## مالی

| اصطلاح | تعریف |
|---|---|
| Charge | بدهی ایجادشده برای دریافت یک خدمت آموزشی |
| Invoice | سند مطالبه شامل یک یا چند قلم |
| Installment | بخش زمان‌بندی‌شده از مبلغ قابل پرداخت |
| Payment | رخداد دریافت یا تلاش برای دریافت وجه |
| Payment Allocation | تخصیص مبلغ یک پرداخت موفق به بدهی یا فاکتور |
| Student Balance | حاصل محاسبه بدهی‌ها منهای تخصیص پرداخت و اعتبار |
| Payment Provider | درگاه فنی دریافت وجه مانند بانک یا Orix Wallet |

وضعیت فاکتور از تخصیص پرداخت‌ها محاسبه می‌شود و با تغییر مستقیم یک فیلد مالی تعیین نمی‌گردد.

## واژه‌های ممنوع یا مبهم

- `Class` به‌تنهایی در کد استفاده نشود؛ از `ClassSection`، `ClassSession` یا `Classroom` استفاده شود.
- `Grade` برای پایه و نمره هم‌زمان استفاده نشود؛ از `GradeLevel` و `Score` استفاده شود.
- `Status` بدون نام دامنه استفاده نشود؛ مانند `EnrollmentStatus` یا `SessionStatus`.
- `User` برای شخص، دانش‌آموز و حساب ورود به‌جای هم استفاده نشود.
